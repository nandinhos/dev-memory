## 4. Pipeline de Curadoria — ✅ COMPLETO E GOVERNÁVEL

```
capture (imutável, idempotência sha256)
  → sanitize (regex determinístico, 12 padrões de segredo; P1 provou que LLM vaza)
  → curate  (AnthropicCurationEngine→MiniMax, structured output + reparo ≤2 tentativas,
             temperature 0.1, retry exponencial em transiente, provenance real)
  → policy  (PromotionPolicy: persist/discard por confiança)
  → dedup   (RecurrenceScorer composto: texto 0.35 + erro 0.25 + causa 0.20 + tech 0.10 + solução 0.10;
             floors TEXT≥0.55/TOTAL≥0.50; "independente" só se commit/dia distintos)
  → doc-val (Context7 RAG; veredito ancorado SÓ nos trechos recuperados; contraditado nunca auto-valida;
             reanálise guiada por IA preserva trilha de auditoria)
  → group   (SkillGroupProposer por IA)
  → compile (SkillCompiler: contrato proíbe inventar fontes)
  → publish (SkillPublisher: git versionado, bump patch, índice README)
```

**Pontos fortes observados no código:**
- `CaptureSanitizer` é **determinístico por design** (decisão documentada: 4 de 5 segredos vazavam com redação via prompt).
- `CurateCaptureJob` tem **tripla rede de proteção**: `failed()` marca capture FAILED; `--retry-failed` re-enfileira; scheduler `memory:process-captures --retry-failed` hourly (requer cron `schedule:run` na VPS — confirmar se ativo).
- `CurationExecution` registra **proveniência real** (provider/model/prompt_version/temperature/usage/hashes) — auditável.
- `DocValidationOutcome` separa "inconclusive" (sem docs) de "contradicted" (docs contrariam) — sem falso apoio.

## 5. Busca e Recuperação — ✅ HÍBRIDA COM RRF

- **Lexical:** `tsvector` gerado + índice GIN, `websearch_to_tsquery` (PostgreSQL); fallback determinístico SQLite p/ dev/teste.
- **Semântica:** pgvector com **espaço canônico versionado** (`provider/model`), validação estrita de dimensão, hash de conteúdo inclui o espaço (troca de modelo invalida vetor antigo), busca filtrada por `embedding_model`.
- **Fusão:** Reciprocal Rank Fusion `k=60`, sem comparar escalas incompatíveis; retorna `search_mode` (hybrid/semantic/lexical/filter).
- **Provedores:** MiniMax `embo-01` (1536) ou Ollama `nomic-embed-text` (768, local/VPS pequena). Timeout 60s p/ CPU, 8s p/ nuvem. Falha de provedor degrada para lexical sem fabricar vetor. ✅
- **HubBriefing:** consulta preventiva determinística (sem LLM), riscos+padrões+lições+skills por stack — ideal para o momento de planejamento.

> **⚠️ Limite atual:** `RecurrenceScorer::findMatch` carrega **todas as memórias com descrição completa em RAM** e roda 5 cossenos por memória (achado #14 da auditoria 2026-07-18, ainda em backlog). Funciona com ~110 memórias; com escala (2º cérebro alimentado por N projetos) fica caro. Candidato natural: busca híbrida + grafo para **candidatos top-K** em vez de full-scan.

## 6. Knowledge Graph — ✅ GOVERNANÇA FORTE

- `knowledge_nodes/edges/evidence` no PostgreSQL (sem banco extra — decisão documentada com critério de reavaliação).
- **Projeção determinística:** memória → nó `memory`; itens de stack → nós `technology`; `applies_to` com evidência. Idempotente, com backfill.
- **Extração de relações por IA é governada:** nasce `proposed`, só `validated` (humano) aparece em `memory_related`; `contradicts`/`supersedes` exigem revisão humana.
- **Consulta explicável:** `memory_related` retorna caminho completo, direção, relação, confiança e evidências; depth ≤3, limit ≤100 (custo previsível).
- **Isolamento de escopo:** memória de projeto acessa próprio projeto + globais; global não expõe privadas; `project_id` nulo não autoriza travessia entre legadas. ✅
- UI admin `/admin/relation-proposals` para aprovar/rejeitar arestas.

## 7. Segurança — ✅ BOA BASE, ⚠️ BACKLOG REGISTRADO

**Confirmado no código (output observado):**
- MCP HTTP **exclusivamente tokenizado** (`mcp.token` middleware; SHA-256 persistido, plaintext exibido 1×, expiração opcional, `last_used_at`).
- `McpAccessPolicy`: token comum = projeto + globais (leitura); **escrita só no próprio projeto**; global = admin apenas. Perfis de harness isolados por `user_id`.
- `memory_delete` **duas fases** (`ConfirmationGuard`: single-use, target-bound, TTL 5min).
- `HarnessProfileService::isSafePath`: rejeita traversal, caminhos absolutos de sistema e `.bashrc`/`.zshrc`/etc. (executam código); allowlist de prefixos.
- `CaptureSanitizer`: 12 padrões (JWT, Bearer, env assignment, PEM, Google/GitHub/AWS/Slack, base64, senha, email).
- Rate limit `throttle:120,1` no `/api/mcp`; payload de config com cap 200KB.
- `AuthenticateMcpToken` → 401 JSON-RPC padrão; `McpController` sem exposição de stack.
- Settings criptografadas em DB (cast `encrypted`), secret write-only na UI.
- `APP_DEBUG=false` em prod (documentado no deploy.md).

**Pendências (registradas no próprio STATUS.md — backlog de segurança):**
1. **Rotacionar token global admin de prod** e demais tokens/chaves que já apareceram em chat.
2. Mover credenciais de prod para env vars via wrapper (nunca hardcoded em config de harness).
3. Reemitir tokens project-bound com escopo mínimo para integrações.
4. Auditar `~/.config/opencode/opencode.json`, `~/.zshrc`, `.mcp.json` por credenciais reais.
5. **HSTS ausente** na resposta (Cloudflare pode injetar); CSP/permissions-policy não configurados.
